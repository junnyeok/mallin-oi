# 오이키우기 MVP

## 게임 개요

오이키우기는 물주기로 경험치를 쌓아 오이 캐릭터를 단계적으로 키우고, 완전히
자란 뒤 수확해 오이 재화를 얻는 모바일 중심 육성형 웹게임이다. 현재
말린오이닷컴 저장소 안에 있지만 기존 사이트,
말린오이캘린더, Android·iOS 앱과 코드를 공유하지 않는 독립 프로젝트 표면으로
구성했다.

## 현재 구현 기능

- 장면 안에서 누른 위치의 물뿌리개·물 효과와 물주기 경험치 획득
- 기존 캐릭터 띠용 애니메이션과 빠른 연속 입력
- 새싹(0 XP) → 애기오이(15 XP) → 어른오이(35 XP) → 수확 가능(50 XP)
- 수확 버튼을 통한 주기당 50 오이 1회 지급과 새싹 초기화
- 5종 시설 구매, 보유량별 가격 상승, 초당 자동 경험치
- 시간 차 기반 자동 경험치와 최대 8시간 오프라인 경험치
- 성장 단계별 투명 배경 캐릭터와 물뿌리개 이미지
- 버전이 포함된 브라우저 로컬 저장
- 페이지 숨김·이탈·자동 저장과 재실행 시 저장 복원
- 수확 가능 상태의 경험치 상한과 보상 중복 지급 방어
- 손상되거나 비정상적인 저장 숫자 방어
- 게임 전용 데이터 초기화
- 320px 이상 모바일 화면, 안전 영역, 키보드 포커스, `aria-live`,
  `prefers-reduced-motion` 대응

## 현재 미구현 기능

- 서버 저장, 계정 로그인, 여러 기기 동기화
- 서버 시간 검증과 치팅 방지
- 시설 이미지와 효과음·배경음
- 물주기 경험치 업그레이드
- 퀘스트, 업적, 환생, 광고, 인앱결제
- 독립 Android·iOS 프로젝트와 네이티브 기능
- 앱스토어 배포 설정

## 로컬 실행

ES Modules를 사용하므로 `file://` 대신 HTTP 서버로 실행한다.

```bash
cd games/cucumber-grow
python3 -m http.server 4173
```

브라우저에서 `http://127.0.0.1:4173/`을 연다.

## 저장 데이터

로컬 저장소 키:

```text
mallinoi_cucumber_grow_save_v1
```

저장 구조:

```javascript
{
  saveVersion: 1,
  cucumbers: 0,
  totalEarned: 0,
  touchYield: 1,
  growthExperience: 0,
  harvestCount: 0,
  facilities: {
    "small-garden": 0,
    "greenhouse": 0,
    "watering-system": 0,
    "smart-farm": 0,
    "processing-factory": 0
  },
  perSecond: 0,
  growthStageId: "sprout",
  lastSavedAt: 0,
  startedAt: 0,
  settings: {}
}
```

`perSecond`와 `growthStageId`는 저장하지만 불러올 때 시설 보유량과
`growthExperience`로 다시 계산해 비정상적인 파생 값을 그대로 신뢰하지 않는다.
기존 v1 저장에는 새 필드가 없으므로 오이 재화, 누적 수확, 터치 수치, 시설,
설정은 유지하고 `growthExperience`와 `harvestCount`만 0으로 보완한다. 저장 키와
`saveVersion`은 그대로 유지한다. 지원하지 않는 저장 버전이나 깨진 JSON은 안전한
초기 상태로 복구한다. 향후 버전이 바뀌면
`saveVersion`별 마이그레이션 단계를 `save-manager.js`에 추가해야 한다.

## 오프라인 보상

마지막으로 게임 진행을 저장한 시각과 다시 활성화한 시각의 차이를 완료된 초 단위로
바꾼 뒤, 마지막 저장 상태에서 검증·재계산한 초당 자동 경험치를 곱한다. 1초 미만의
이탈은 보상 0으로 처리해 `0개` 보상 모달이 뜨지 않게 한다.

```text
보상 = min(max(현재 시각 - 마지막 저장 시각, 0), 8시간) × 초당 자동 경험치
```

보상을 적용하면 계산 시각을 즉시 현재 시각으로 옮기고 바로 저장하므로 같은 경과
시간이 연속 적용되지 않는다. 자동 경험치는 50 XP에서 멈추며 초과분은 다음 성장
주기로 넘기지 않는다. 초당 자동 경험치가 0이거나 이미 수확 가능하면 보상도 0이다.

## 현재 보안 한계

MVP는 서버가 없는 로컬 전용 게임이다. 저장 JSON과 기기 시간은 사용자가 바꿀 수
있으므로 보상과 재화를 신뢰할 수 있는 보안 경계로 사용하면 안 된다.
`offline-reward.js`에도 로컬 시간 기반이라는 주석을 남겼다.

정식 앱에서는 서버가 발급한 시각, 서버에 저장된 마지막 활동 시각, 서버가 검증한
시설 상태를 기준으로 오프라인 보상을 계산해야 한다. 저장 요청 재전송 방지,
비정상 시간 이동 감지, 최대 보상 정책 검증도 서버에서 수행해야 한다.

## 기존 프로젝트와의 격리

- 게임은 `games/cucumber-grow/` 밖의 HTML, CSS, JavaScript, 이미지, 음원,
  Supabase 코드를 import하거나 참조하지 않는다.
- 기존 루트 HTML과 서비스 메뉴에 게임 링크를 추가하지 않았다.
- 기존 공용 CSS와 `tokens.css`를 불러오지 않는다.
- Supabase 클라이언트, 로그인, 피클, 상점, 인벤토리를 사용하지 않는다.
- 기존 서비스 워커를 등록하지 않고 캐시 목록도 수정하지 않았다.
- 기존 Capacitor 설정의 `webDir`은 `www`이며, `www` 준비 스크립트가 `games/`를
  복사하지 않으므로 기존 Android·iOS 앱 자산에 포함되지 않는다.
- 게임 파일을 `www/`, `android/`, `ios/`에 복사하지 않았다.
- 로컬 저장소 키가 기존 사이트 키와 겹치지 않도록 게임 이름을 포함했다.

저장소 루트에는 `.nojekyll`과 `CNAME`이 있어 GitHub Pages를 루트에서 게시하는
설정이라면, 게임 파일을 `main`에 커밋·배포할 때 직접 URL로 공개될 가능성이 있다.
기존 루트 서비스 메뉴에는 게임 링크가 없지만, 배포 후 경로를 아는 사용자는
`/games/cucumber-grow/` 주소로 접근할 수 있다.
또한 기존 루트 서비스 워커는 게임을 사전 캐시 목록에 넣지는 않지만, 루트 범위의
같은 출처 HTML 요청을 네트워크 우선 방식으로 런타임 캐시한다. 따라서 게임이
`mallin-oi.com/games/...`로 실제 배포되고 사용자가 방문하면 게임 HTML이 기존
HTML 캐시에 들어갈 수 있다. 하위 게임 코드만으로 상위 범위 서비스 워커를 안전하게
제외할 수 없으므로, 완전한 런타임 캐시 격리에는 별도 출처 배포 또는 기존 서비스
워커의 명시적 경로 제외가 필요하다. 후자는 이번 범위에서 수정하지 않았다.
정적 배포에도 절대 포함하면 안 되는 출시 전략이라면 기존 배포 설정을 임의로
변경하지 말고 다음 중 하나를 별도 작업으로 선택한다.

1. 게임을 별도 저장소로 이동한다.
2. 사이트 배포를 명시적 허용 목록 기반 빌드 산출물로 전환한다.
3. 사이트와 게임을 서로 다른 브랜치·호스트·배포 파이프라인으로 분리한다.

## 독립 Android·iOS 앱 전환 단계

1. 게임 폴더를 별도 저장소로 분리할지 결정한다.
2. 현재 최소 `package.json`을 독립 개발 서버와 빌드 출력 설정까지 확장한다.
3. 게임 전용 앱 ID와 버전 체계로 새 Capacitor 프로젝트를 생성한다.
4. 새 Android·iOS 플랫폼을 추가하고 기존 캘린더 프로젝트는 재사용하지 않는다.
5. 앱 아이콘, 스플래시, 화면 방향, 안전 영역을 제작·검증한다.
6. 앱 일시정지·재개를 `main.js`의 저장/복귀 함수에 네이티브 어댑터로 연결한다.
7. 서버 저장과 저장 버전 마이그레이션을 설계한다.
8. 서버 시간 기반 오프라인 보상과 서버 검증을 구현한다.
9. 로그인과 계정 동기화를 추가한다.
10. 진동, 사운드, 광고 또는 인앱결제를 각각 독립 어댑터로 추가한다.
11. 개인정보 처리방침, 데이터 삭제 절차, 스토어 고지를 준비한다.
12. 실제 기기, 앱 종료, 백그라운드, 시간대 변경, 업데이트 마이그레이션을 검증한다.

서버 연동 시에는 계정별 게임 상태, 시설 보유량, 저장 버전, 서버 기준 마지막 활동
시각, 검증된 오프라인 보상 이력을 개념적으로 분리한다. 이번 단계에서는 SQL 파일,
테이블, RPC를 만들지 않는다.

## 이미지와 사운드 교체

캐릭터는 단계에 따라 `cucumber-baby.png`, `cucumber-boy.png`, `cucumber.png`를
사용하고 물주기에는 `water-gun.png`와 `water.png`를 사용한다. 포인터의 X·Y를
게임 장면 내부 비율로 변환해 누른 위치에 효과를 놓고, 보이는 효과가 가장자리에서
잘릴 때만 최소 거리만큼 안쪽이나 위쪽으로 보정한다. 중앙선 왼쪽은 오른쪽 아래,
중앙선과 오른쪽은 왼쪽 아래로 물을 보내며 오이의 위치나 성장 크기는 목표 계산에
사용하지 않는다. `water.png`는 왼쪽 위에서 오른쪽 아래로 행 우선 재생하는
4열×2행, 8프레임 스프라이트다. 프레임마다 다른 투명 여백은 실제 첫 물 픽셀이
16도 기울어진 물뿌리개 주둥이에 고정되도록 보정한다. 물뿌리개는 820ms 재생
안에서 기울었다가 복귀하며, 오른쪽 모션은 이 전체 구성을 수평 반전한다. 단계
상태와 자산 경로, 경험치 기준, 터치 경험치, 수확 보상은 `game-config.js`에서
관리한다.

- 이미지: `assets/images/`
- 사운드: `assets/sounds/`

전용 자산을 추가한 뒤에도 게임 폴더 내부 상대 경로만 사용한다.

## 데이터 초기화

화면 아래 `플레이 정보 > 개발용 도구 > 게임 데이터 초기화`를 누르고 확인한다.
브라우저 개발자 도구에서는 다음 한 줄로도 게임 데이터만 지울 수 있다.

```javascript
localStorage.removeItem("mallinoi_cucumber_grow_save_v1");
```

## 수동 테스트 항목

- 320×568, 375×667, 390×844, 데스크톱에서 가로 스크롤과 겹침이 없는지
- 캐릭터 마우스·터치·키보드 활성화가 입력당 한 번만 누적되는지
- 누른 위치의 물뿌리개·물 효과·XP 숫자와 띠용 애니메이션이 표시되는지
- 15/35/50 XP에서 캐릭터와 성장 상태가 정확히 바뀌는지
- 수확 연속 입력에도 50 오이가 한 번만 지급되고 새싹으로 돌아가는지
- 오이가 부족한 시설 버튼은 비활성화되는지
- 시설 연속 구매 후 가격, 보유량, 초당 자동 경험치가 즉시 바뀌는지
- 탭이 느리거나 백그라운드였다가 돌아와도 시간 차만큼 XP가 쌓이는지
- 새로고침 후 보유 오이, 시설, 경험치와 성장 단계가 복원되는지
- 마지막 저장 시각을 과거로 바꾼 테스트에서 오프라인 모달이 한 번만 표시되는지
- 8시간보다 긴 경과 시간은 8시간까지만 지급되는지
- 경험치가 수확 기준을 넘어도 50 XP에서 멈추는지
- 초기화 취소 시 유지되고 확인 시 게임 전용 데이터만 사라지는지
- 손상된 JSON, 음수, `NaN`, 무한대에 안전한 초기값이 적용되는지
- 개발자 도구 콘솔에 오류와 누락된 파일 요청이 없는지

핵심 로직 테스트:

```bash
npm test
```
