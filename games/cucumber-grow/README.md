# 말린오이: 오이키우기

`games/cucumber-grow/`는 iOS·Android 독립 게임 앱과 데스크톱 개발 미리보기가 함께
사용하는 게임 원본이다. 고정된 세로 화면 안에서 HUD·월드·도구·하단 메뉴를 레이어로
구성하며, 문서 전체가 아닌 텃밭 월드 카메라만 위아래로 움직인다.

## 원본과 생성 결과

- 게임 원본: `games/cucumber-grow/`
- 독립 모바일 래퍼: `apps/cucumber-grow-mobile/`
- 웹 빌드 결과: `apps/cucumber-grow-mobile/dist/`
- Capacitor 생성 결과: 모바일 래퍼의 `android/app/src/main/assets/public/`,
  `ios/App/App/public/`
- 저장소 루트 `android/`, `ios/`, `www/`: 기존 말린오이 캘린더 앱

HTML·CSS·JavaScript·게임 이미지·사운드는 이 디렉터리에서만 수정한다. `dist/`와
플랫폼 `public/`은 `npm run cap:sync`가 다시 만들므로 직접 수정하지 않는다. 게임
번들에는 서비스 워커와 원격 사이트 파일을 포함하지 않는다.

## 화면과 조작

- 시작 화면 뒤 메인 텃밭이 바로 열리며 상단 HUD와 하단 게임 메뉴는 고정된다.
- 텃밭은 한 행에 3개다. 네 번째 텃밭부터 다음 행에 놓인다.
- 월드에서 9px 이하의 짧은 입력만 탭으로 판정하고, 그보다 큰 세로 이동은 카메라
  드래그로 처리한다. `pointercancel`과 멀티터치는 행동을 취소한다.
- 성장 중인 오이를 누르면 물뿌리개가, 위협 캐릭터를 누르면 뿅망치가 자동으로
  사용된다. 장비 영역은 보유 상태만 보여 주며 조작 모드를 바꾸지 않는다. 시설만
  설치할 항목을 고른 뒤 텃밭 위치를 누른다. 데스크톱 미리보기에서는 마우스 클릭과
  휠도 같은 입력으로 동작한다.
- 시설, 인벤토리, 도감, 상점, 설정은 URL 이동 없이 앱 내부 전체 화면 장면으로
  열린다. 팝업과 장면이 열리면 뒤쪽 월드 입력이 차단된다.
- Android 뒤로가기는 팝업 또는 장면을 먼저 닫고, 메인에서는 게임 종료 확인창을
  연다. iOS 하위 화면에는 항상 닫기 버튼이 있다.

## 게임 규칙

- 낮 90초 → 밤 60초 → 준비 시간 순서다. 준비 시간은 사용자가 `준비 완료`를
  누르기 전까지 자동으로 끝나지 않는다.
- 빈 텃밭을 누르면 오이를 심는다. 성장 중인 오이를 누를 때마다 쿨타임 없이 물 1을
  소비해 작물 XP 1을 준다. 다 자란 오이를 누르면 수확한다.
- 기본 지급 도구는 물뿌리개와 공격력 1의 뿅망치다. 새·다람쥐·멧돼지는 낮,
  도둑은 밤에 텃밭 장면 바깥에서 접근한다. 캐릭터를 직접 눌러 체력을 모두 줄이면
  접근·먹기/훔치기·피격·쓰러짐 연출 뒤 제거된다.
- 준비 시간에만 오이 판매, 텃밭·시설·물·연료·에너지 구매가 가능하다.
- 가격, 경험치, 턴 시간, 시설 범위, 자원 소비와 해금 레벨은
  `js/game-config.js`의 `GAME_CONFIG`에서 관리한다.

### 도구와 시설

| 항목 | 해금 | 가격 | 실제 효과 |
| --- | ---: | ---: | --- |
| 물뿌리개 | 1 | 기본 지급 | 오이 터치 시 자동 사용, XP 1, 물 1, 쿨타임 없음 |
| 뿅망치 | 1 | 기본 지급 | 위협 터치 시 자동 사용, 1회 공격력 1 |
| 스프링클러 | 3 | 240코인 | 주변 8칸 낮 성장, 물 0.25/초 |
| 빗물통 | 3 | 180코인 | 준비 단계 진입 시 물 18 충전 |
| 허수아비 | 4 | 380코인 | 주변 8칸 낮 위협 확률 70% 감소 |
| 발전기 | 5 | 600코인 | 연료 0.2/초로 에너지 1/초 생산 |
| 온실 | 6 | 900코인 | 3열×2행, 밤 성장, 에너지 0.5/초 |

스프링클러가 겹쳐도 같은 작물에 성장 XP를 중복 지급하지 않는다. 시설은 물·연료·
에너지가 없으면 정지 상태와 이유를 표시한다. 온실 설치는 필요한 여섯 칸과 다른
시설의 충돌을 검사하며 기존 작물을 지우지 않는다.

각 위협의 체력·속도·탐지 종류·사운드·스프라이트·기존 피해 수치는
`js/game-config.js` 한 곳에서 관리한다. 목표 오이가 사라지면 다른 심어진 텃밭을
찾고, 남은 목표가 없으면 피해 없이 장면 밖으로 퇴장한다. 쓰러짐 보상은 빠른 연속
터치에도 한 번만 지급된다.

## 저장 스키마 v4

설치 앱은 Capacitor Preferences에 리비전·작성 시각·체크섬을 가진 두 슬롯을
번갈아 저장한다. 최신 슬롯이 쓰기 도중 손상되면 이전 정상 슬롯을 복구한다. 행동
뒤에는 디바운스 저장을 예약하고, 주기 저장과 백그라운드 전환에서는 큐를 비운다.

기존 저장 키 `mallinoi_cucumber_grow_save_v1`은 삭제하지 않는다. 같은 WebView에
v1·v2·v3 localStorage 저장이 있으면 작물, 텃밭, 레벨, 경험치, 재화, 도구, 시설,
위협과 현재 턴을 v4로 한 번 정규화해 네이티브 슬롯에 옮긴다. 마이그레이션은 기본
도구나 보상을 중복 지급하지 않는다. 브라우저 개발 모드에서는 같은 어댑터가
localStorage를 저장 백엔드로 사용한다.

웹사이트 브라우저 저장소와 설치 앱 WebView 저장소는 자동으로 공유되지 않는다.
다른 설치나 기기로 옮길 때는 설정의 JSON 백업 내보내기·가져오기를 사용한다. 앱
삭제 시 기기 저장도 삭제될 수 있다. 계정 로그인과 Supabase 클라우드 동기화는 현재
게임에 없으므로 불완전하게 추가하지 않았다.

## 생명주기와 오프라인 진행

백그라운드에서는 반복 타이머와 BGM을 중지하고 즉시 저장한다. 복귀 시 저장 기준
시각과 현재 시각의 차이를 계산한 뒤 단일 타이머만 다시 시작한다. 오프라인 진행은
최대 8시간이고 준비 단계를 건너뛰지 않으며, 기기 시계가 크게 뒤로 이동한 경우
보상을 만들지 않는다. 네트워크 없이도 심기·성장·수확·상점·저장이 동작한다.

## 사운드, 진동, 접근성

배경음악은 Web Audio로 생성하고 로컬 WAV 및 짧은 합성 효과음을 사용한다. 첫
사용자 입력 뒤에만 오디오를 활성화하며 같은 효과음의 동시 재생을 제한한다. BGM,
효과음, 진동, 각 음량과 움직임 줄이기 설정은 저장된다. 기기가 진동이나 오디오를
지원하지 않아도 시각 피드백만으로 계속 플레이할 수 있다.

전투 효과음은 `scripts/generate-combat-audio.mjs`가 생성한 22.05kHz 모노 16-bit
PCM WAV 원본이다. 새·다람쥐·멧돼지는 접근음을 사용하고 도둑 접근은 의도적으로
무음이다. 뿅망치·물주기·갉아먹기 효과는 제한된 오디오/DOM 풀을 재사용한다.

모든 핵심 버튼은 최소 44 CSS px이며 safe-area, `100dvh`, 고대비 상태 아이콘,
접근성 이름과 `prefers-reduced-motion`을 지원한다. CSS 토큰은 `css/game.css`의
`:root`에 모두 정의한다.

## 개발 미리보기

저장소 루트에서 정적 서버를 실행한다.

```bash
python3 -m http.server 4173
```

```text
http://127.0.0.1:4173/games/cucumber-grow/
```

모듈 CORS 때문에 `index.html`을 `file://`로 직접 열지 않는다.

## 검사와 모바일 빌드

```bash
cd games/cucumber-grow
npm test
find js tests -type f \( -name '*.js' -o -name '*.mjs' \) -exec node --check {} \;
```

```bash
cd apps/cucumber-grow-mobile
npm install
npm run cap:sync
npm run build:android
npm run build:ios:sim
```

모바일 앱의 작업명은 `말린오이: 오이키우기`, 임시 개발 식별자는
`com.mallinoi.cucumbergrow.dev`, 개발 버전은 `0.1.0 (1)`이다. 운영 앱 이름,
Bundle ID, 버전과 서명은 출시 전에 별도로 확정한다. 루트 캘린더 앱 버전과
`SITE_VERSION`은 이 게임 빌드와 무관하며 변경하지 않는다.

## SQL과 원격 서비스

게임은 로그인·Supabase·서비스 워커·원격 이미지 URL에 의존하지 않는다. 따라서
이번 앱 전환에는 SQL이나 RLS 변경이 필요하지 않다. 계정 기반 클라우드 백업을
추가할 때는 별도 저장 테이블, 사용자별 RLS, 리비전 충돌 정책을 먼저 설계해야 한다.
